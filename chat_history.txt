### Root Cause of the Bug

   When `enableHighAccuracy: true` is set, Chromium browsers attempt to communicate with hardware GPS or low-level Windows Geolocation sensors. On standard PCs and laptops without GPS chips or with slow Wi-Fi triangulation, the browser times out or throws error code 2 (`POSITION_UNAVAILABLE`) or code 3 (`TIMEOUT`) **even after the user clicked "Allow"**.
2. **Treating All Geolocation Errors as Denial**:
   The previous error callback blindly treated every error as `denied` (`setLocationPermissionState('denied')`). Because `error.code !== 1` was not distinguished, granting permission was accidentally treated as a denial, locking the screen into the "Location Permission Required" gate and forcing repeated requests.
3. **No Persistent Permission Query or Caching**:
   If permission was already granted in browser settings, the app was not checking `navigator.permissions.query({ name: 'geolocation' })` or caching the approved status, causing an initial indeterminate state and repeated triggers on reload.
