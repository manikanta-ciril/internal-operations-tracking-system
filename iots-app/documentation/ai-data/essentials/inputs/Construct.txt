-----------------------------------------------------------------------------------------
INTELLIGENCE & ANALYSIS LAYER
-----------------------------------------------------------------------------------------
    
    PURPOSE
    -------
    The Intelligence and Analytical Layer converts operational records generated by the
    IOTS into measurable performance indicators, workload insights, attendance patterns,
    exceptions, risks, trends, and management reports.
    
    This layer does not directly perform day-to-day work operations.
    Instead, it analyzes the records created by the Management Layer and presents
    meaningful information to Employees, Managers, and higher-level management according
    to their authorized scope.
    
    The layer should support:
    - Historical analysis
    - Current operational analysis
    - Trend identification
    - Performance measurement
    - Workload analysis
    - Attendance analysis
    - Exception detection
    - Risk classification
    - Management reporting
    - Role-based visibility
    - Drill-down from summary information to underlying records
    
    
    1. PERFORMANCE ANALYTICS
    ========================
    
    FUNCTION
    --------
    Performance Analytics measures how effectively an individual employee, manager,
    team, role, or organizational unit is completing assigned work against defined
    expectations.
    
    The system should not rely on a single performance value. It should combine
    multiple measurable indicators so that performance represents actual work outcomes
    rather than only task volume.
    
    
    1.1 TASK COMPLETION RATE
    ------------------------
    
    Definition:
    Measures the percentage of assigned tasks that were completed within the selected
    analysis period.
    
    Logic:
    
    Completion Rate =
    (Number of tasks completed / Number of tasks that were due or assigned for the
    selected measurement period) × 100
    
    Handling Logic:
    - Identify all tasks belonging to the selected employee, manager, team, role, or
      organizational scope.
    - Determine which tasks fall inside the selected reporting period.
    - Count tasks whose final workflow outcome is Completed / Closed.
    - Count tasks that were expected to be completed during that period.
    - Exclude cancelled tasks from completion calculations where cancellation is an
      administrative outcome rather than employee non-completion.
    - Reassigned tasks should retain their history and ownership information.
    - Reassignment must not create duplicate task counts.
    - Display the result together with the total number of tasks used in the calculation.
    - Allow the user to drill from the percentage into the underlying task records.
    
    Possible Output:
    - Completion Rate: 91%
    - Completed: 41
    - Expected: 45
    - Remaining: 4
    
    
    1.2 ON-TIME COMPLETION
    ----------------------
    
    Definition:
    Measures how many completed tasks were completed on or before their applicable
    deadline.
    
    Logic:
    - Compare the actual completion/approval timestamp against the task deadline.
    - A task completed on or before the deadline is classified as On-Time.
    - A task completed after the deadline is classified as Late.
    - Tasks whose deadlines were officially extended should use the latest authorized
      deadline for the final comparison, while retaining the original deadline in
      historical records.
    - Tasks that became overdue and were later completed remain visible as late
      completions.
    - Display both on-time percentage and late-completion count.
    
    Output:
    - On-Time Completion Rate
    - Late Completion Rate
    - Number of tasks completed on time
    - Number of tasks completed late
    - Average delay duration for late tasks
    
    
    1.3 AVERAGE COMPLETION TIME
    ---------------------------
    
    Definition:
    Measures the average time required to move tasks from active execution to
    completion.
    
    Logic:
    - Determine the defined start point for the task.
    - Determine the actual completion point.
    - Calculate the elapsed completion duration.
    - Where the workflow records blocked/waiting periods, the reporting logic may
      distinguish total elapsed time from active work time.
    - Use a consistent business definition throughout the organization.
    - Do not mix gross elapsed duration and active work duration without explicitly
      labelling them.
    - Display the average together with task volume because a small sample can distort
      interpretation.
    
    Output:
    - Average completion time
    - Median completion time where supported
    - Fastest completion
    - Longest completion
    - Comparison with previous period
    
    
    1.4 TARGET-BASED PERFORMANCE
    ----------------------------
    
    Definition:
    Measures actual achievement against a defined target.
    
    Examples:
    - Number of tasks expected
    - Tasks completed
    - Daily target
    - Weekly target
    - Monthly target
    - Role-specific operational target
    
    Logic:
    - Retrieve the target applicable to the selected employee, role, team, or period.
    - Determine actual achieved value.
    - Compare actual achievement against target.
    - Calculate achievement percentage.
    
    Target Achievement =
    (Actual achievement / Defined target) × 100
    
    Handling:
    - Targets should be period-specific.
    - Targets should be role-aware where different roles have different expectations.
    - Changes to targets should preserve their historical versions.
    - Reports should indicate the target used for the calculation.
    - A target of zero must not produce an invalid division result.
    - Where no target exists, show "Target Not Configured" instead of assuming zero.
    
    Output:
    - Target
    - Actual
    - Achievement %
    - Variance from Target
    - Above / On Target / Below Target
    
    
    1.5 EMPLOYEE-SPECIFIC PERFORMANCE
    ----------------------------------
    
    Definition:
    Provides an individual employee performance view.
    
    Logic:
    - Filter all permitted task, attendance, activity, and performance records for the
      selected employee.
    - Combine relevant indicators.
    - Show performance over the selected period.
    - Compare the employee with their own historical performance.
    - Where organizational policy permits, compare against applicable team or role
      benchmarks.
    - Do not expose information outside the viewer's authorized scope.
    
    Possible Indicators:
    - Task completion rate
    - On-time completion
    - Average completion time
    - Target achievement
    - Overdue task count
    - Reassignment frequency
    - Blocker frequency
    - Work activity consistency
    - Attendance indicators
    
    
    1.6 MANAGER-SPECIFIC PERFORMANCE
    --------------------------------
    
    Definition:
    Measures managerial effectiveness based on team-level operational outcomes.
    
    Logic:
    - Aggregate performance of employees under the manager's authorized scope.
    - Measure task allocation effectiveness.
    - Measure overdue and blocked work.
    - Measure review and approval activity.
    - Measure resolution of employee issues.
    - Measure team target achievement.
    - Compare current team performance with previous periods.
    - Do not evaluate the manager solely from employee task completion count.
    
    Possible Indicators:
    - Team completion rate
    - Team on-time completion
    - Overdue workload
    - Review turnaround time
    - Reassignment frequency
    - Issue resolution time
    - Team target achievement
    - Team workload balance
    
    
    1.7 TEAM PERFORMANCE
    ---------------------
    
    Definition:
    Provides an aggregated performance view for a team.
    
    Logic:
    - Group employee records by team.
    - Aggregate task and performance indicators.
    - Show distribution rather than only a single team average.
    - Identify whether poor team results originate from a few employees or are broadly
      distributed.
    - Allow drill-down:
      Team → Employee → Task → Activity / Evidence
    
    
    1.8 ROLE-BASED PERFORMANCE
    --------------------------
    
    Definition:
    Measures performance according to the work type and expectations applicable to
    a specific role.
    
    Logic:
    - Identify the user's authorized role/designation.
    - Apply the performance metrics configured for that role.
    - Avoid forcing identical KPIs onto roles with fundamentally different work.
    - Preserve a common reporting structure while allowing role-specific measures.
    
    Example:
    A BDE may be measured using lead/task outcomes,
    while a Graphic Designer may be measured using creative-task completion,
    revision cycles, submission quality, and deadline adherence.
    
    
    2. TASK & WORKLOAD ANALYTICS
    ============================
    
    FUNCTION
    --------
    Task and Workload Analytics analyzes how work is distributed, how much work is
    pending, where bottlenecks exist, who is overloaded, and how effectively assigned
    work is progressing.
    
    The layer should distinguish between:
    - Task quantity
    - Task status
    - Workload
    - Work progress
    - Task ownership
    - Reassignment history
    
    
    2.1 TASK DISTRIBUTION
    ---------------------
    
    Definition:
    Shows how tasks are distributed across employees, teams, managers, roles,
    priorities, and statuses.
    
    Logic:
    - Group tasks by the selected dimension.
    - Count tasks in each group.
    - Allow filtering by:
      - Date
      - Employee
      - Manager
      - Team
      - Role
      - Priority
      - Status
    - Show both task count and percentage of total.
    - Permit drill-down into the underlying task list.
    
    Example:
    Team A = 40%
    Team B = 35%
    Team C = 25%
    
    
    2.2 PENDING TASK ANALYSIS
    -------------------------
    
    Definition:
    Measures work that remains incomplete.
    
    Logic:
    - Identify tasks that are not in a final completed/closed state.
    - Separate normal active work from exceptions such as overdue or blocked work.
    - Group pending tasks by employee, team, priority, age, and deadline.
    - Highlight long-pending tasks.
    - Allow drill-down to task details.
    
    
    2.3 OVERDUE TASK ANALYSIS
    -------------------------
    
    Definition:
    Identifies tasks whose applicable deadline has passed without completion.
    
    Logic:
    - Compare current/reporting timestamp with the current authorized task deadline.
    - If the task remains incomplete after the deadline, classify it as Overdue.
    - Overdue tasks should not be treated merely as ordinary pending work.
    - Record:
      - Overdue date
      - Duration overdue
      - Priority
      - Current owner
      - Manager
      - Whether the task was reassigned
      - Whether a manager intervention occurred
    - Sort or classify overdue tasks by severity.
    - Provide a direct path from analytics to manager intervention.
    
    
    2.4 REASSIGNMENT FREQUENCY
    --------------------------
    
    Definition:
    Measures how frequently tasks are reassigned.
    
    Logic:
    - Count reassignment events from the task history.
    - Do not count a reassigned task as multiple tasks.
    - Count each actual ownership-transfer event separately.
    - Calculate:
      - Total reassignment events
      - Number of tasks reassigned
      - Reassignments per task
      - Reassignment by employee/team/manager
    - Identify repeated reassignment patterns.
    - Preserve the reason and history of every reassignment.
    
    This can identify:
    - Capacity problems
    - Assignment problems
    - Unclear ownership
    - Workflow problems
    - Repeated operational intervention
    
    
    2.5 PARTICULAR-EMPLOYEE WORKLOAD
    -------------------------------
    
    Definition:
    Measures the amount and intensity of work assigned to a specific employee.
    
    Logic:
    - Retrieve all tasks currently assigned to the employee.
    - Categorize by:
      - Active
      - Pending
      - Overdue
      - High priority
      - Blocked
      - Waiting for review
    - Consider deadlines and task priority rather than simply counting tasks.
    - Show current workload and historical workload.
    - Compare current workload against the employee's configured/expected capacity,
      where such capacity information exists.
    
    Possible Output:
    Employee
    Current Tasks
    High Priority Tasks
    Overdue Tasks
    Blocked Tasks
    Upcoming Deadlines
    Workload Level
    
    
    2.6 TEAM WORKLOAD
    -----------------
    
    Definition:
    Measures the distribution of active work across the team.
    
    Logic:
    - Aggregate employee workload records.
    - Compare workload across team members.
    - Identify concentration of work on individual employees.
    - Identify employees with significantly lower or higher active workload.
    - Show task volume alongside deadline pressure.
    - Provide a manager drill-down from:
      Team → Employee → Tasks
    
    
    2.7 WORKLOAD BALANCE
    --------------------
    
    Definition:
    Determines whether assigned work is reasonably distributed.
    
    Logic:
    - Calculate workload indicators for all applicable employees.
    - Compare workload against configured capacity or expected workload.
    - Classify employees as:
      - Normal
      - High
      - Overloaded
      where the actual thresholds are configurable.
    - Generate management attention when workload becomes materially unbalanced.
    - Do not automatically reassign work solely because an analytical threshold is
      reached; analytics should identify the condition, while authorized management
      actions perform the reassignment.
    
    
    2.8 UPCOMING WORKLOAD
    ---------------------
    
    Definition:
    Predicts near-term workload pressure from tasks whose deadlines are approaching.
    
    Logic:
    - Identify upcoming deadlines.
    - Group tasks by employee/team.
    - Consider task priority and due-date proximity.
    - Detect concentration of deadlines within a short period.
    - Flag employees likely to become overloaded.
    - Present this as an operational warning rather than a confirmed failure.
    
    
    3. ATTENDANCE ANALYTICS
    =======================
    
    FUNCTION
    --------
    Attendance Analytics analyzes attendance records, working hours, late arrivals,
    absences, availability, and workforce attendance patterns.
    
    Attendance and Availability must remain separate concepts.
    
    Attendance answers:
    "Was the employee present / working?"
    
    Availability answers:
    "Can the employee currently accept or handle work?"
    
    
    3.1 LATE ARRIVAL TRENDS
    -----------------------
    
    Definition:
    Identifies patterns in late arrivals over time.
    
    Logic:
    - Retrieve attendance check-in records.
    - Determine whether each arrival was on time or late using the organization's
      configured working schedule and applicable grace period.
    - Count late events by:
      - Employee
      - Team
      - Role
      - Date
      - Week
      - Month
    - Show trend over time.
    - Distinguish occasional late arrivals from repeated patterns.
    - Link back to attendance records for verification.
    
    
    3.2 ABSENCE TRENDS
    ------------------
    
    Definition:
    Measures absence patterns across employees and teams.
    
    Logic:
    - Identify attendance records classified as absent.
    - Group by employee, team, role, and reporting period.
    - Distinguish approved leave from unexplained/flagged absence where the system
      contains that information.
    - Show frequency and trend.
    - Do not treat approved leave automatically as poor performance.
    
    
    3.3 AVAILABILITY PATTERNS
    -------------------------
    
    Definition:
    Measures how employee availability changes throughout working periods.
    
    Logic:
    - Analyze recorded availability states such as:
      Available
      Busy
      In Meeting
      On Break
      In Training
      Do Not Disturb
      Working Remotely
      On Leave
      Absent
      Offline
    - Measure duration/frequency where such timestamps are available.
    - Identify recurring periods of low availability.
    - Compare availability with workload and task deadlines.
    
    
    3.4 WORKFORCE ATTENDANCE PATTERNS
    ----------------------------------
    
    Definition:
    Provides an aggregated view of workforce attendance behavior.
    
    Logic:
    - Aggregate attendance records across teams, roles, branches, or departments.
    - Identify:
      - Attendance rate
      - Late-arrival patterns
      - Absence patterns
      - Remote/off-site patterns where recorded
      - Working-hour trends
    - Compare current period with historical periods.
    - Identify recurring organization-level patterns.
    
    
    3.5 WORK HOURS ANALYSIS
    -----------------------
    
    Definition:
    Measures recorded working duration for employees and teams.
    
    Logic:
    - Use check-in and check-out records.
    - Account for recorded break periods where supported.
    - Calculate work duration according to the organization's configured attendance
      policy.
    - Show:
      - Total hours
      - Average hours
      - Daily hours
      - Team totals
    - Flag incomplete or inconsistent attendance records separately instead of
      silently treating them as zero hours.
    
    
    4. EXCEPTION / RISK ANALYSIS
    ============================
    
    FUNCTION
    --------
    Exception and Risk Analysis identifies operational conditions that require
    attention.
    
    It converts raw operational conditions into manageable warnings.
    
    The system should distinguish between:
    - Normal operation
    - Attention required
    - High-risk operational condition
    
    Risk classification should be rule-based and configurable unless a formal
    predictive model is implemented.
    
    
    4.1 OVERDUE TASK DETECTION
    --------------------------
    
    Logic:
    - Continuously or periodically evaluate active task deadlines.
    - Detect tasks whose deadline has passed without completion.
    - Calculate overdue duration.
    - Consider task priority.
    - Consider whether the task is blocked, awaiting review, or otherwise subject
      to a valid workflow condition.
    - Create an analytical exception where appropriate.
    - Notify or surface the exception to the authorized manager dashboard.
    - Track whether the exception was resolved, extended, reassigned, or escalated.
    
    
    4.2 WORKLOAD RISK
    -----------------
    
    Definition:
    Identifies situations where an employee/team may not have sufficient capacity
    to handle assigned work within expected deadlines.
    
    Logic:
    - Evaluate active task count.
    - Evaluate upcoming deadlines.
    - Evaluate priority.
    - Evaluate overdue tasks.
    - Evaluate blocked work.
    - Compare workload against configured capacity where available.
    - Combine the conditions into a workload-risk assessment.
    
    Example logic:
    High active workload
    +
    multiple approaching deadlines
    +
    existing overdue work
    =
    Higher workload risk
    
    
    4.3 REPEATED REASSIGNMENT RISK
    ------------------------------
    
    Definition:
    Detects when a task or employee is repeatedly involved in reassignment events.
    
    Logic:
    - Count reassignment events over a configurable period.
    - Determine whether the configured threshold has been exceeded.
    - Identify:
      - Task repeatedly reassigned
      - Employee frequently receiving reassigned tasks
      - Employee frequently losing assigned tasks
      - Team-level reassignment concentration
    - Record the reason wherever available.
    - Create a risk/attention indicator when the configured threshold is reached.
    - Do not interpret reassignment automatically as employee failure; the reason
      must remain available for management review.
    
    
    4.4 RISK CLASSIFICATION
    -----------------------
    
    The system can classify detected exceptions into:
    
    LOW
    ---
    Indicates a condition that should be monitored but does not currently require
    urgent intervention.
    
    MEDIUM
    ------
    Indicates a recurring or materially important condition that should receive
    manager attention.
    
    HIGH
    ----
    Indicates a condition that requires immediate managerial or authorized higher-level
    attention.
    
    Handling Logic:
    - Risk level is generated from configured business rules.
    - Rules may consider:
      - Severity
      - Frequency
      - Duration
      - Priority
      - Impact
      - Repeated occurrence
    - Risk thresholds should be configurable.
    - Every risk result should show why it was classified at that level.
    - Risk should be traceable to underlying operational records.
    - Risk status should be capable of moving through:
      Detected → Reviewed → Action Taken → Resolved
    - Resolved risks remain in historical records for trend analysis.
    
    
    4.5 PENDING REQUEST RISK
    ------------------------
    
    Definition:
    Identifies requests that remain undecided beyond the expected handling period.
    
    Examples:
    - Leave request
    - Permission request
    - Resource request
    - Task clarification request
    
    Logic:
    - Determine request creation time.
    - Determine expected decision/response period where configured.
    - Identify requests that remain pending beyond that period.
    - Group by request type, requester, manager, and age.
    - Surface delayed requests to the appropriate authority.
    - Preserve request history and decisions.
    
    
    4.6 UNRESOLVED BLOCKER ANALYSIS
    -------------------------------
    
    Definition:
    Identifies employee-reported issues/blockers that remain unresolved and may
    impact work completion.
    
    Logic:
    - Detect active blocker/issue records.
    - Measure blocker age.
    - Identify affected task.
    - Identify employee and responsible manager.
    - Determine severity.
    - Determine whether escalation has occurred.
    - Prioritize blockers based on severity, task priority, and duration.
    - Surface long-running blockers as management exceptions.
    
    
    4.7 COMBINED OPERATIONAL RISK
    -----------------------------
    
    The system may combine multiple independent exceptions to identify a larger
    operational concern.
    
    Example:
    
    Employee has:
    - High workload
    - Multiple approaching deadlines
    - Existing overdue task
    - Open blocker
    
    The analytical layer can combine those conditions into a higher-priority
    management attention item.
    
    Important:
    This does not automatically mean the employee is underperforming.
    The system identifies the operational condition and allows management to inspect
    the underlying causes.
    
    
    5. TREND & HISTORICAL ANALYSIS
    ==============================
    
    FUNCTION
    --------
    Historical analysis compares current operational performance with previous periods
    to identify improvement, deterioration, recurring patterns, and changes.
    
    Logic:
    - Store historical analytical snapshots or calculate from historical operational
      records.
    - Compare:
      - Current day vs previous day
      - Current week vs previous week
      - Current month vs previous month
      - Current period vs equivalent previous period
    - Show direction:
      - Improving
      - Stable
      - Declining
    - Allow drill-down into the records causing the trend.
    
    
    5.1 PERFORMANCE TRENDS
    ----------------------
    
    Analyze:
    - Completion rate over time
    - On-time completion over time
    - Target achievement over time
    - Average completion time over time
    
    
    5.2 WORKLOAD TRENDS
    -------------------
    
    Analyze:
    - Task volume over time
    - Pending workload
    - Overdue workload
    - Reassignment frequency
    - Workload concentration
    
    
    5.3 ATTENDANCE TRENDS
    ---------------------
    
    Analyze:
    - Attendance rate
    - Late-arrival frequency
    - Absence frequency
    - Availability patterns
    - Working-hour trends
    
    
    5.4 RISK TRENDS
    ---------------
    
    Analyze:
    - Number of detected risks
    - Low / Medium / High distribution
    - Repeated risk types
    - Average resolution time
    - Unresolved exception count
    - Recurrent operational problems

    8. DATA HANDLING LOGIC
    ======================
    
    The analytical layer should read from operational records rather than manually
    re-entering information.
    
    Primary analytical sources include:
    - User records
    - Role and authorization records
    - Task records
    - Task state history
    - Work activity records
    - Work notes
    - Effort/time records
    - Supporting documents/evidence
    - Attendance records
    - Availability records
    - Requests
    - Approval records
    - Blockers/issues
    - Escalation records
    - Reassignment history
    - Audit records
    - Configured targets
    - Configured working schedules
    
    
    8.1 STATE-AWARE ANALYSIS
    ------------------------
    
    The analytical layer must understand the difference between task states.
    
    Examples:
    Assigned
    Pending / In Progress
    Overdue
    Reassigned
    Completed
    
    Operational execution may additionally contain:
    Blocked
    Waiting for Review
    Under Review
    Changes Requested
    Issue Resolved
    Done / Closed
    
    Reassigned should be treated as a workflow event/history rather than counting the
    same task as a new task.
    
    Overdue should be treated as an exception requiring attention rather than simply
    another normal task category.
    
    
    8.2 HISTORICAL PRESERVATION
    ---------------------------
    
    Analytical results must be traceable to historical operational records.
    
    When task assignments, deadlines, priorities, roles, or other operational values
    change:
    - Current values should represent the current state.
    - Historical values should remain available for analysis.
    - Reports should be able to explain why historical results changed.
    - Reassignment, deadline extension, review, and approval history should not be
      destroyed.
    
    
    8.3 AUDIT TRACEABILITY
    ----------------------
    
    Every important analytical result should be traceable back to its source data.
    
    Example:
    
    Risk = HIGH
        ↓
    Reason:
        - 3 overdue tasks
        - 2 high-priority deadlines approaching
        - 1 unresolved blocker
        ↓
    Underlying Records:
        Task IDs
        Blocker ID
        Workload Records
        Attendance / Availability Records where relevant
    
    This allows management to verify the analytical conclusion rather than treating
    the dashboard value as unexplained.
    
    
    9. MANAGEMENT ATTENTION / ACTION CENTRE
    =======================================
    
    The analytical layer may provide an "Operational Attention" area that highlights
    items requiring human review.
    
    Possible attention items:
    - High-risk workload
    - Overdue critical tasks
    - Repeated reassignment
    - Long-pending requests
    - Unresolved blockers
    - Attendance anomalies
    - Declining performance trend
    - Significant target variance
    
    Each item should provide:
    - What happened
    - Who/what is affected
    - Why it was flagged
    - Risk level
    - When it occurred
    - Current status
    - Authorized next action
    - Link to underlying record
    
    
    10. INTELLIGENCE MATURITY
    =========================
    
    The Intelligence and Analytical Layer can be implemented in progressive levels.
    
    LEVEL 1 — DESCRIPTIVE ANALYTICS
    --------------------------------
    Answers:
    "What happened?"
    
    Examples:
    - 40 tasks completed
    - 5 tasks overdue
    - 3 requests pending
    - Attendance rate = 94%
    
    
    LEVEL 2 — DIAGNOSTIC ANALYTICS
    ------------------------------
    Answers:
    "Why is it happening?"
    
    Examples:
    - Overdue work concentrated in one employee
    - Reassignment increased during the last week
    - Delays are associated with unresolved blockers
    - Team workload is unevenly distributed
    
    
    LEVEL 3 — PREDICTIVE / ADVANCED ANALYTICS
    ------------------------------------------
    Answers:
    "What is likely to happen?"
    
    Examples:
    - Employee may become overloaded
    - Deadline risk is increasing
    - Repeated blockers may affect completion
    - Current workload may create a future overdue condition
    
    Predictive functionality should only be labelled as predictive/AI when an actual
    predictive model or appropriate analytical method is implemented.
    
    Rule-based thresholds and condition checks should remain clearly identified as
    rule-based analytics.
