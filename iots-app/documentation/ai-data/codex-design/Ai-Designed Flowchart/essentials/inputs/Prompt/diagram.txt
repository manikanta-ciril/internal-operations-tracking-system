**Version 2: Spatial Layout, Visual Grammar & Draw.io XML Specifications**

**System Role & Objective:**
You are an Elite Enterprise Systems Architect and UI/UX Visual Modeler equipped with `drawio-mcp`. Your objective is to programmatically generate a `.drawio` XML file representing the complete Internal Operations Tracking System (IOTS) for CIRIL.

This diagram must be highly encyclopedic in its logic but **completely comprehensible to a layman or non-technical end-user**. It must map the exact business processes (Authentication, Geolocation, Role Routing, Task Workflows, Reassignment, and Approvals) using a specific, highly readable spatial layout.

### I. VISUAL GRAMMAR & STYLING RULES

To ensure the diagram is beautiful, approachable, and non-intimidating:

1. **Typography:** Use `Verdana` for all node text to ensure clean, crisp readability. Use `Architects Daughter` (or a similar sketched/handwritten font) for edge labels and structural layer titles to give it an approachable, "blueprint" feel.
2. **Shapes:**
* Use **Ellipses** exclusively for START/END nodes.
* Use **Rhombuses (Diamonds)** exclusively for Decision Gates (e.g., "Validate Credentials", "Task Completed?").
* Use **Rounded Rectangles** for all actionable tasks, processes, and dashboards to maintain a modern, friendly aesthetic.
* Use large **Transparent Rectangles with Dashed Borders** (dash pattern 8 8) as bounding boxes for macro-layers.


3. **Connectors (Edges):** Use orthogonal edge styles (`edgeStyle=orthogonalEdgeStyle`) with rounded corners (`rounded=1`) and block-thin arrows. Avoid spaghetti routing; lines must travel cleanly along horizontal and vertical axes.
4. **Color Palette:** Keep fill colors minimalist (white or transparent) with dark text. Use subtle color coding only if necessary for status (e.g., Green for Valid/Approved, Red/Amber for Invalid/Overdue).

### II. SPATIAL ARRANGEMENT & MACRO STRUCTURE

The diagram must be divided into two primary vertical zones, flowing top-to-bottom.

#### **LAYER 1: The Authentication & Authorization Layer (Top Bounding Box)**

* **Container:** A wide, dashed bounding box titled "Authentication & Authorization Layer".
* **Flow (Top-Down & Left-to-Right):**
1. **START** (Ellipse) connects downwards to **User Logs into the System**.
2. Connects to **Validate Credentials** (Rhombus).
* *Branch Left (Invalid):* Connects to **Notify: Invalid Credentials**, which loops back up to START.
* *Branch Down (Valid):* Connects to **Validate Location** (Rhombus).


3. **Validate Location** (Rhombus).
* *Branch Left (Unknown/Off-site):* Connects to **Mark the session as "Remote/Off-site"**.
* *Branch Down (Known/On-site):* Connects to **Audit log-in and location coordinates**. (The off-site node also routes here to ensure all logins are audited).


4. Connects downwards to **Decide User Role** (Rhombus). A wedge callout floating nearby should read: *"Decides role based on User Credentials"*.
5. **Role Split:** The Decision node branches into three distinct horizontal paths leading to the three main Dashboards in Layer 2.



#### **LAYER 2: The Management & Operations Layer (Massive Bottom Bounding Box)**

* **Container:** A massive dashed bounding box taking up the lower 75% of the canvas, titled "Management Layer".
* **Headers:** Place three large, bold rounded rectangles horizontally across the top of this layer:
* `[ADMIN - DASHBOARD]` (Left)
* `[MANAGER - DASHBOARD]` (Center)
* `[EMPLOYEE - DASHBOARD]` (Right)



### III. MICRO-STRUCTURES & COLUMN LAYOUTS

Below the three dashboard headers, arrange the functional modules in vertical columns.

#### **Column 1: Admin Dashboard (Left Side)**

Create vertical sub-groups of nodes connected by orthogonal lines to represent the Admin's operational domains. Provide clear layman descriptions.

* **User Management:** Create New User -> Set Roles & Permissions -> Activate/Deactivate Account -> Reset Password.
* **Global Task Management:** Monitor all tasks -> Select specific task for intervention -> Edit/Reassign/Cancel -> Force-approve completed work.
* **Location & Attendance Control:** Set office coordinates (Geofences) -> Define working hours -> Monitor daily attendance -> Review flagged/remote logins.
* **System Settings:** Access system registry -> Create new roles/designations -> Manage report settings -> Update notification templates.
* **Security & Audit Viewer:** Access secure logs -> Apply filters -> Review login histories -> Export specific security reports.

#### **Column 2: Manager Dashboard (Center Side)**

This is the core operational engine of IOTS. It must be highly detailed.

* **Team Management:** View Team Members -> View Profiles -> View Current Assignments -> View Workload & Availability.
* **Performance Monitoring:** Monitor task completion rate -> Review overdue tasks -> Track deadlines -> Give feedback.
* **Team Communication:** Send team announcements -> Share task instructions -> Send automated deadline reminders.
* **Workload Management:** View Employee Workload -> Identify Overloaded Employees -> Check Availability -> Balance Task Distribution -> Reassign if required.
* **Task Management & Workflow (The Core Engine):** Map the task state machine exactly as follows:
1. *Create a Task* -> *Set Priority & Due Date* -> *Assign to Employee* -> *Notify Employee*.
2. *Task Status (Rhombus)* -> Branches to (Assigned) and (Pending/In Progress).
3. Connect to the Employee workflow (in Column 3).



#### **Column 3: Employee Dashboard & Task Execution (Right Side)**

Show how the execution staff interacts with the system, connecting back to the Manager column for approvals.

* **Work Management:** Tasks Dashboard / Queue -> Get Task Details -> Task Execution -> Task Submission (Upload evidence/files).
* **The Execution Loop:**
1. *Employee works and updates about task*.
2. *Task Completed? (Rhombus)*.
* *No:* Loop back to working.
* *Yes:* Triggers *Manager Reviews Task* (Moves visually back to the Manager column).


3. *Approved? (Rhombus)* (Under Manager).
* *Yes:* Complete and close task -> Store changes in audit log.
* *No:* Provide Feedback/Corrections -> Loops all the way back to *Employee works and updates about task*.




* **Exception Handling (Blockers & Overdue):**
1. *Issue? (Rhombus)* -> *Raise Issue-Ticket* -> *Manager Intervention? (Rhombus)*.
2. *Yes:* Assign Severity -> Escalate to Higher Authority or Resolve.
3. *Reassign Task? (Rhombus)* -> Choose new Employee -> Loops back to *Employee works*.



### IV. ENCYCLOPEDIC LOGIC & AUDIT INTEGRATION

To ensure the diagram reflects the full intelligence of IOTS as described in the enterprise blueprints:

1. **The Immutable Audit Log:** Create a dedicated node at the very bottom of the diagram called **"Store changes in audit log"**. Route dashed lines from critical actions (Logins, Approvals, Reassignments, Role Changes) directly into this single node to visually represent "Immutable Accountability."
2. **Layman Terminology:** Do not use database terminology (e.g., `Update SQL`, `POST Request`). Use process terminology (e.g., `Employee works and updates about task`, `Check Employee Workload`).
3. **Role Labels:** On the connection lines routing from `Decide User Role` to the Dashboards, explicitly label the edges `(User: Admin)`, `(User: Manager)`, and `(User: Employee)` to make the routing logic instantly obvious to a non-technical viewer.
